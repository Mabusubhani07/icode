# Contributing to iCode

Thank you for wanting to contribute to iCode — a free programming mastery platform focused on deep learning of C and DSA.

Please follow these guidelines to make contributions easy to review and accept.

1. Code of Conduct
   - Be respectful and constructive.

2. How to contribute
   - Fork the repository and create a feature branch named `feat/<short-description>` or `fix/<short-description>`.
   - Keep changes small and focused.
   - Run linters and tests before creating a PR.

3. Pull Request Process
   - Open a Pull Request against the `main` branch (or default branch).
   - Provide a clear title and description explaining the change and motivation.
   - Link related issues using `#<issue-number>`.
   - Use the checklist in PR description when applicable (e.g., tested, linted, documented).

4. Coding style
   - Frontend: TypeScript + React (Next.js) style; prefer Prettier for formatting and ESLint for linting.
   - Backend: TypeScript (Node) or Go; prefer idiomatic code and include types where relevant.

5. Issue templates
   - Use the issue templates in .github/ISSUE_TEMPLATE when opening new issues.

6. Development setup (local)
   - Install Node.js LTS (if working on frontend/backend).
   - Install dependencies and run the dev server as described in the README.

7. Tests
   - Add tests for new features and bug fixes where applicable.

8. Security
   - Do not commit secrets or credentials. Use environment variables and secrets management.

If you need help getting started, open an issue and tag it with `help wanted`.
